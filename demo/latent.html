Why a sidecar? Similarity alone does not decide

The pointComparing the text with the words "yes" and "no" is close to a coin flip on most questions (about 53% on tone with e5-small). Learning which numbers matter for each question is what turns the same vectors into answers.

The arithmetic, with 4 made-up numbers

Real vectors have 384 numbers; the steps are the same. Each answer gets a score: multiply the text's numbers by another row, number by number, and add them up (a dot product).

#1#2#3#4score
Text: "over our budget, forty thousand"0.80.1-0.30.5
Cosine · option "yes, mentions a price"0.60.20.10.40.67
Cosine · option "no, does not"0.70.1-0.10.30.75 · picks no ✗
Sidecar · weights learned from Clef2.1-0.4-1.50.22.19 − 1.0 offset = 1.19 → P(yes) 0.77 ✓

"Yes, mentions a price" and "no, does not" share almost every word, so their vectors are nearly the same and the winner is decided by noise. The sidecar's weights are not words at all: they are learned from Clef's answers, so they point straight at what separates yes from no for this one question.

What each readout below means

Cosine the text against each answer's wording, every number weighted equally. No training.
Bias-corrected the same, minus each answer's score for an empty text, so a built-in lean cancels. No training.
Whitened first evens out the space so no direction dominates, then cosine. No training.
Learned (the sidecar) one weight per number, fitted on Clef's or people's answers. What BitMob uses.
Under the hood: how a Jev-class model reads the same request

Both end in the same arithmetic: one score per allowed answer, turned into probabilities. What differs is what goes in and how the scores are weighted. A Jev-class model puts the text, the question and every option in one sequence, so each option is read with the text. Our engine reads the text once and lets the sidecar decide; the diagrams below show both.

Jev-class model (kev's open code; Jev's own internals are not published)

State, question and every option sit in one sequence. Each option reads the state and the question but not the other options; the decide token reads everything (the arcs). So each option's vector already knows the text.

score_k = (W_k · h_opt_k) · (W_q · h_decide) / 16 learned W, 256-dim pointer space

Embedding readout (what the research below measures)

Question and text go in together; the vector q is the model's last hidden state at the final token (Qwen3-Embedding uses last-token pooling). Each option is embedded on its own, without seeing the text.

score_k = Σ_d w_d · q_d · o_k,d (+ b_k) cosine: every w_d = 1, no b · learned: one w_d per dimension plus a per-option offset b_k
1 · Option read in contextJev-class: yes. Embedding: no, the option never sees the text.
2 · What the readout seesBoth boil the input down to a few vectors. Jev-class: one per option plus a decide vector, all read with the text. Embedding: one for question + text, one per option read alone.
3 · How dimensions are weightedJev-class: learned (kev projects both vectors into a 256-dimension space first). Cosine: every dimension equally. The readouts below change only this.

No training at all? Ask five ways

The pointWith no training, asking five ways lifts the big Qwen 4B encoder from 63% to 80% on tone, Clef's level. But it needs a GPU; the trained sidecar gets there on a CPU.

How to read this

One question is one line through the space. Here the same question is asked five ways, each written before any was scored: the original, its opposite, two rephrasings and one adjacent question. The scores are then corrected, combined and checked against each other. Yes/no sets only.

The terms, in plain words
CalibrationCorrecting a model's built-in lean so its scores and percentages mean what they say. The bias step here is contextual calibration (Zhao et al. 2021).
EnsemblingAsking several variants and combining the answers. With reworded questions this is prompt ensembling, or test-time augmentation in general.
Consistency checkingA statement and its opposite must agree (P(yes) + P(opposite yes) = 1). Used to find the “truth direction” without labels in Contrast-Consistent Search (Burns et al. 2022).
Learned trust (stacking)A tiny model that weighs each angle by how reliable it has been. Five weights, fitted on 80% of the items and scored on the rest.

One column per item, sorted by the combined score. Blue votes yes, orange votes no; stronger colour, stronger vote. Bottom row is the true answer. Columns where the angles split are the uncertain items.

Do the angles add information?

Correlation between angles across items (1 = always move together). Angles that move together repeat each other and add little; a combination only helps where they differ but are each right more often than not.
