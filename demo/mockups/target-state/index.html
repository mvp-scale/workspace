The knowledge pipeline as one record

Every article becomes one knowledge record: a stack of layers over one clean text, each layer written once by one named element and read by every later element and by the next article. The outputs of axis A (what it is about: Domain, Area, Subarea, Capability), axis B (what it says and does: Function, Condition, Claims, Evidence, Place, Time, Novelty) and the World engine keys are derived from the layers, never recomputed per output. Click any name for its point, definition and measure.

Vocabulary, used exactly: a BitMob model is a small CPU classifier answering one question (BitMob Domain, Function, Condition, Area, Capability, Novelty; plus the Place student). A BitTool is a fixed-rule program, never a classifier. A lookup is a table match. The Fuser combines votes into one calibrated proposal per head; the Decider (Lean-verified, unchanged) turns it into answer, provisional or abstain; the Router orders who answers. The teacher labels offline only. Dashed names are proposed new elements. No LLM runs at read time; everything is CPU.

Compare view: grey TODAY values are read from files (projects/world-state/runs/pulse/golden/articles.jsonl and the generator listed in README.txt); blue TARGET values are a hand-written specification, produced by no model. Status badges: works, partly, not built. UNVERIFIED marks a claim this page could not check in a file.

The sections below are the detailed target design. The element cards still list the Entity linker, Ontology matcher and Fuser; read them as conditional.

1. The record: eight layers, each written once

Read bottom-up: text and metadata, tokens and sentences, mentions, linked entities, relations and events, claims, the article profile, the cross-article graph. Each layer says who writes it, the one-time computation, who reads it, and how it is built and tested.

2. The reuse matrix: producer by consumer

Rows are the layers that produce information; columns are the elements and outputs that read it. A filled cell says what is read. Every output reads several rows; no output recomputes a row.

3. The cross-article loop: what accumulates and feeds the next article

The journal is the memory. Each table below grows with every article and is read by a named layer of the next one, so article N+1 is cheaper (duplicates exit, candidates are narrowed) and better (aliases, priors, counts).

4. Every output derived from the layers

Each card names the layers it reads, the derivation rule, how it is tested, and the four golden stories. TARGET is the specification; TODAY (compare view) is the value stored in the files.

5. The cascade with early exit

Cheap first. The BitTools always run (evidence is never skipped); the encoder runs once and only when a head is still open; the teacher sees only what the Decider withheld. The BitTools are also labelling functions: cheap votes that the Fuser weighs per head on held-out splits (publisher, event and time), Snorkel style.

    6. Measured tests per layer

    Bars are set before a run. Public sets are scoring only, never training. Agreement with a teacher is not accuracy and is named as agreement.
