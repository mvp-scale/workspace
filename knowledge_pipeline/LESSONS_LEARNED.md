## 2026-11-09 and 10 (loop session)
- **Smoke-test the save step.** T73 stage 1 lost 22 minutes of work because the result file was written last and failed (numpy integers in JSON). Run every new script on 5 items through to its output file before the full run. Add switches for item count and output folder for this.
- **One owner of a row's end.** Do not put a process id on a heartbeat row if the script closes the row itself: the poller marks any row whose process ends without a finish call as failed, which made a finished T72 run look failed.
- **A hung or silent job needs its own watcher.** A job nobody watches is only caught after the overdue grace (10 min). The health loop (`kit/live/health.py`) flags it; a watcher closes it within seconds.
- **Sealed set: one read, and look for degenerate outputs first.** The T37 composed row fell back to "predict every item yes" (threshold -1) and used up the sealed read. Check the chosen threshold and the number of yes calls on dev before reading sealed.
- **Check the n.** Duplicate ids in an items file made n larger than the label count (T71); compare n with the gold file before trusting an interval.
- **A decision field with no defect named is not a finding.** MM3 severity came back above "low" at p 0.34 on two code reviews with no failing question; report it as unsure, do not drill it, and do not claim the gate passed.
- **Say what the key mixes.** Entity keys that fall back to text keys for unmapped phrases lower the match rate (T73); a union rule is the fair comparison, and it must be labelled post-hoc.
- **Display words must match the state.** "running" hard-coded after every row hid that Kaggle rows were queued; a flat 10-minute stale rule flagged finished and always-on rows. Each row now states how often it should report.
- 2026-11-10: size a chain's cap from the measured time per arm times the number of arms times 1.5, and close the heartbeat row from an EXIT trap, not at the end of the script. T81's 55 minute cap killed its last arm and left the row saying running.
- 2026-11-10: select among many arms on one file and report on another (T81); the embedder and term text did not move the ontology mapping, so test cheap levers before building around them, and name the miss-case that points at the real limit.

## 2026-11-10 — a runner's heartbeat row had no state, so health said "nothing running" during a live job
- Runners T82b and T83 called `heartbeat.beat(job, progress=..., last="running")` with no `state`, `where` or `every_s`. The row never counted as running, the health line said NOTHING RUNNING, and the owner read it as hung.
- Rule: a runner's first beat sets `state="running"`, `where`, `every_s`, `why`, `success`. After launch, read `health.py`; it must say WORKING and name the job.

## 2026-11-10 — run_round.py --dry-run launched the real job
- The runner skipped only the ledger notes in a dry run and still ran the card command, so the T90 job started before its prediction note was written. It was caught within two minutes and the order was disclosed (L1666).
- Rule: a dry run validates the card and prints; it never runs the command. Fixed in run_round.py. Check a dry run with `ps` before trusting the word.

## 2026-11-10 — finished jobs stayed on the Live view as "done" rows
- Scripts and card commands ended with heartbeat.beat(state="done"), which keeps the row until the 24 hour prune. A job that ends calls heartbeat.finish(job, "done"|"failed"), which moves it to the history and removes the row; smoke runs call heartbeat.drop(job).
- Rule: first beat sets state running; last call is finish or drop, never a beat with a final state.
