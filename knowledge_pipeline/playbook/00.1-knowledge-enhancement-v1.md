# 00.1 Knowledge enhancement: managing knowledge systematically and visually

Created 2026-11-24. Status: active. Owner of record: the project owner. Ledger task: T158.

## Why this file exists
Playbook 00 (`00-knowledge-pipeline-v1.md`) is the pipeline of record and is **not changed** by this file. Work so far turned article streams into structured knowledge, but delivering that knowledge to a reader kept failing (metadata instead of meaning, layouts tuned to one example, no tracked plan).

This file isolates one enhancement: how knowledge is **broken down** (systematic) and **delivered** (visual) across any source and any area, at scale. It plugs into named 00 stages and does not create a second pipeline.

## Why this is separate from 00
| Reason | Detail |
|---|---|
| 00 is proven and gated | Its stages, bars and decider are the record. Mixing exploratory work into it would blur what is proven. |
| This work is still uncertain | Meaning (level 7) and ranking (level 9) have no accuracy yet, and the presentation has failed three times. |
| One-example risk | 13 of 53 components were tuned on two areas. The enhancement must prove generality before it changes the pipeline of record. |
| One track, not two | Every round extends a named 00 stage (table below). Nothing here runs outside the 00 pipeline or its gates. |
| Clean promotion | A round that passes its gate on unseen data becomes a dated 00 addendum, with the owner's yes. |

## Delivery (visual)
- A view is one combination of three states:
  - **reader state:** first look / since last look / deep dive
  - **knowledge state:** new / moving / settled / disputed / gap
  - **scale:** one development / one area / all areas
- Each requirement has an information type (change, magnitude, time, entity, place, cause, connection, contradiction, certainty, forward, gap). Each type maps to one visual encoding (`design/presentation-process/type-encoding-rules.json`).
- A view never invents a missing level. It shows the gap instead.

## Standing rules (every round)
1. Parameters are frozen and also tested on an unseen window. A gate that passes only on the tuned areas does not pass. (MM3-0756)
2. No area, story, publisher or event-class word in code. Lexicons are data with provenance and a lexicons-off test.
3. Each round names its 00 stage, a gate, a pass bar stated before it runs, and an outside truth.
4. No model-written text in the render path unless the owner approves D1. Until then, quotes and typed slots only.
5. Every round is ≤ 1 hour of compute, with a prediction before it runs and a score after. Results are recorded in the ledger.
