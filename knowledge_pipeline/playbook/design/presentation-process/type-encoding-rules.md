# Type -> encoding rule table (rendered from type-encoding-rules.json)

The core building block: information type -> proven visual encoding + the minimal text it needs. One hue is reserved for 'new since last look'; one hue for 'disputed'; lightness of one neutral hue for certainty. Every mark carries its word or number (redundant coding). Citations in sources.md.

| id | information type | mark | minimal text | why | sources |
|---|---|---|---|---|---|
| E1 | change | Rank position (changed first) + one reserved accent hue dot before the title + a time-strip dot ring on the days after the cut | '+N new since <cut day>' or 'nothing new since <cut day>' | Position and a single colour pop out preattentively; ordering lets the reader stop early | Shneiderman 1996; Healey & Enns 2012; Treisman & Gelade 1980; TAC 2008 update summarization; Few 2006 |
| E2 | magnitude | Counts <= 5: one dot per unit (subitizing). Counts > 5: horizontal bar on a common aligned scale across all cards. Never area, never colour alone | The number and its unit ('4 independent owners') | Length on a common scale is read most accurately; dots up to 4-5 are counted at a glance | Cleveland & McGill 1984; Heer & Bostock 2010; Kaufman et al. 1949 |
| E3 | time | Dot per day on ONE shared horizontal day axis used by every card (small multiples); dot size by articles that day; the cut shown as a vertical rule | '<first day>-<last day>, N days' | Position on an aligned scale; small multiples make cards comparable without re-reading an axis | Cleveland & McGill 1984; Tufte 1983; Aigner et al. 2011 |
| E4 | entity | Categorical chip, shape by kind: circle = person, square = organisation; names, never counts | The entity label | Shape is a nominal visual variable; a name is what the reader can act on | Bertin 1967; Munzner 2014 ch.5; consume-mockups results 2026-11-23 (counts failed T4) |
| E5 | place | Diamond chip in its own row, labelled 'where'; a map only when coordinates exist (today: none in the data, so no map) | The place label | Spatial data should use its own geometry when available; otherwise keep places apart from actors so 'where' and 'who' are not confused | Munzner 2014 ch.8; Bertin 1967; ledger L2997 |
| E6 | relation-cause | Left-to-right arrow chain; the connective word on the arrow: 'because / led to' = causes, 'after' = precedes (time order only) | The quoted source sentence; speaker when read | Arrows are read as causal or sequential direction; diagrams make inference by locality cheaper than prose | Larkin & Simon 1987; Tversky et al. 2000; Heiser & Tversky 2006; ledger L2995 connectives |
| E7 | connection | The identical chip (same label, same shape) repeated across cards, plus 'also in: <development>' under the chip; at scale (> 20 developments) an entity x development matrix lens | 'also in <development title>' | Similarity groups across space (Gestalt); matrices beat node-link for dense or large graphs | Wertheimer 1923 / Koffka 1935; Ghoniem, Fekete & Castagliola 2004; consume-mockups D4 result |

| E11 | gap | Muted, italic line in the slot where the content would be; never an empty slot and never a hidden slot | 'no <X> read in N articles' | An absent slot is ambiguous (not shown or not known); coherence: say the absence once, plainly | terminology.md gap rule; Mayer 2009 coherence principle; ICD 203 (2015) D.a.3 gaps |

## Composition rules

| id | rule | sources |
|---|---|---|
| C1 | Overview first: a header line with counts (moved / disputed / with forward statement) and a situation strip (one square per development in rank order, filled by state), then ranked cards, then compact lines, then thin developments collapsed | Shneiderman 1996; Nielsen 2006 progressive disclosure |
| C2 | At most 8 full cards above the fold line (changed or disputed first); every other development is one compact line with the same marks (E1, E2, E3, E9) so the scan grammar does not change with scale | Cowan 2001 (4 +/- 1 chunks); Tufte 1983 small multiples |
| C3 | Each card is a fixed block order: remember-line, status line, time strip, who/where, dispute, cause, ahead, since-last-look lines, evidence (details on demand) | Mayer 2009 segmenting and spatial contiguity; Wertheimer 1923 proximity and enclosure |
| C4 | Text sits next to its mark (never a separate legend for a value); one legend for the three reserved colours only | Mayer 2009 spatial contiguity; Ware 2012 |
| C5 | No decoration, no stock imagery, no model-written prose in the render path; every text node is a quote, a label from the fixed vocabulary, or a slot filled from a field | Mayer 2009 coherence; ledger L2995 |
| C6 | Phone width: same block order, columns stack; the situation strip wraps; the shared day axis stays shared | artifact-design contract (16px gutter) |

## Synthesis safety

- S1 Only two kinds of synthesized text: a remember-line, which is a verbatim best-supported source sentence, and a status line composed from fixed slots filled by typed fields.
- S2 Every synthesized line cites the assertion ids it rests on (data-cites attribute, shown on demand).
- S3 Grounding check on every build: every text node is (a) a verbatim data string, (b) a word of the fixed template vocabulary, or (c) a number equal to a data field. Fail = the page is not written.
- S4 Entailment pre-screen (local Clef, free): for a sample of status lines, 'is the line supported by these evidence sentences?'; anything below 0.6 is listed in the build report; the lexical check (S3) remains the gate.
- S5 Confidence words follow ICD 203 and map from sourcing only: single source = low, reported = moderate, established = high, disputed = disputed (low). Likelihood words (Kent / ICD 203 ladder) are never emitted: the data has no probability basis; the slot prints 'likelihood not assessed'.
- S6 'Why it matters to you' needs reader priorities; without them the slot prints 'not assessed (no reader priorities given)'; with a follow list it prints 'touches followed: <entities>' only.
- S7 When a type has no data for a development the slot prints the E11 gap line; nothing is inferred to fill it.
